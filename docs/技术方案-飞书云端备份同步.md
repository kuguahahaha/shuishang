## 〇、先回答你的风险问题

### 结论 1：GitHub Pages 本身不是风险源，**「浏览器直接调飞书写入」才是**

| 误解 | 事实 |
|---|---|
| 「托管在 GitHub 上所以有风险」 | ❌ 换任何静态托管（腾讯云 COS、CloudBase 静态站、Vercel）都一样——**浏览器里跑的 JS 谁都能 F12 看到**。托管在哪不是风险本质 |
| 「那放自己服务器就安全了」 | ❌ 前端代码照样公开。**只要凭据在浏览器里，就是公开的** |
| 「所以不能上传」 | ✅ **能上传**——前提是飞书凭据不进前端 |

### 结论 2：纯静态页 **无法** 安全直连飞书写入
1. **凭据泄露**：`app_secret` 写在前端 → 任何访客都能拿到 → 可读写甚至清空你的表格
2. **跨域限制**：飞书开放 API 不支持浏览器直连，必须服务端中转

### 结论 3：解法是加一个**零成本的免费云函数**
```
Record.html
  ├─ localStorage  ← 主数据源（即时、离线可用）
  └─ 待同步队列 → CloudBase 云函数（★密钥只在这）→ 飞书多维表格
```
> **一句话**：托管在哪不重要，**凭据放哪才重要**。

## 一、使用场景（已按你的确认调整）

```
牌友A的手机 ─┐                        ┌─→ 飞书多维表格（你统一查看）
牌友B的手机 ─┼→ localStorage → 云函数 ┤
牌友C的手机 ─┘   （各自录各自桌）      └─→ 云函数（校验口令 + 审计）
你的手机    ─┘
```

| 确认项 | 结论 |
|---|---|
| 飞书账号 | **个人版飞书**（可建自建应用，够用） |
| 同步方向 | **单向备份**：本地 → 飞书（不回读） |
| 鉴权方式 | **统一口令**（私下分发，首次输入一次） |
| 使用者 | **牌友各自录**（每人用自己手机） |
| 数据归属 | 按 **日期 + 场次 + 桌号** 分组，一桌一人录 |

**各方看到的**：
- 牌友：只看到自己录的数据（不回读），录完自动同步，无感
- 你：在飞书里看到**所有桌**的数据，按日期/场次/桌号筛选汇总
- 牌局的账：每桌各自算自己的筹码差额（应到人数各自填），互不干扰

## 二、口令机制（替代白名单审核）

### 2.1 口令怎么工作
```
① 牌友首次打开网页 → 弹框「请输入同步口令」
② 她输入你私下给的口令 → 前端用 Web Crypto 算 SHA-256 哈希
   ★ 只把【哈希】存本地，之后每次请求带哈希，明文口令不落盘、不进网络
③ 云函数比对哈希（云端存的是同一哈希值，不是明文）
   → 一致：放行写入
   → 不一致：拒绝，返回「口令错误」
```

| 设计点 | 为什么 |
|---|---|
| 口令明文不落盘 | 前端只存哈希，浏览器被翻也拿不到明文 |
| 云端只存哈希 | 云函数被读也拿不到明文口令 |
| 口令强度要求 | ≥ 8 位随机字符（大小写+数字），避免被猜 |

### 2.2 口令怎么改（换设备 / 泄露时）
口令哈希值存飞书「设备表」里，改一行即可：

| 步骤 | 操作 |
|---|---|
| 改口令 | 在飞书「设备表」把「当前口令哈希」改成新哈希 → **所有设备下次请求被拒**，重新输入新口令即可 |
| 停用某人 | 在「设备表」把该 deviceId 的状态改为「停用」→ 该设备立刻无法写入（口令仍有效，但此设备被单独拉黑） |
| 查是谁写的 | 「设备表」记录每个 deviceId 的首次时间、最近时间、累计写入行数；「记录表」每行带「来源设备」 |

> 所以 **deviceId 仍然记录**，但角色从"准入门槛"变成"**审计与单独停用**"——口令管准入，deviceId 管追责。

### 2.3 口令的风险与缓解
| 风险 | 缓解 |
|---|---|
| 口令在群里转发扩散 | ① 口令按桌/按季更换；② deviceId 可单独停用；③ 表格里数据一旦有问题，能定位到具体设备 |
| 牌友换手机 | 新设备首次要再输一次口令（输入框会记住哈希，直接放行） |
| 哈希被撞库 | 口令 ≥8 位随机字符 practically 撞不动 |

> **比白名单省事**：你不用逐个审核，谁要用就把口令给她。

## 三、数据归属与去重（多人录的核心）

### 3.1 分组键
飞书「记录表」里用 **日期 + 场次 + 桌号** 三字段分组：

| 日期 | 场次 | 桌号 | 昵称 | ... |
|---|---|---|---|---|
| 2026-10-29 | 下午场 | A | captain | ... |
| 2026-10-29 | 下午场 | B | nuy | ... |

→ 你在飞书里按「日期 + 场次」筛选，就能看到当天所有桌；按「桌号」筛选就是某一桌。

### 3.2 唯一键与去重
```
唯一键 = 日期 + 场次 + 桌号 + 昵称
```
- 同一键重复推送 → **upsert 覆盖**，不会产生重复行
- 两人误录同一桌同一人 → 后写的覆盖先写的（按 updatedAt）

### 3.3 需要你定的一条规则 ⚠️
**「一桌只由一人录」** —— 这是避免两个人同时录同一桌打架的唯一办法。

实际操作上：
- 牌局开始时你（或组织者）在群里说清：**A 桌谁录、B 桌谁录**
- 每人打开网页自己填：日期、场次、桌号（如 B）、应到人数
- 桌号统一用 A/B/C，场次名统一用「下午场/晚上场」（或直接填"第2桌"）

> 如果你希望更省事，也可以让每个人只录**自己负责的玩家**（比如只有 5 个人），但那样"差额校验"要在你这边汇总时才完整。**我建议按桌分**，每桌自校验，最不容易乱。

## 五、同步机制（无感 + 不丢数据）

### 5.1 主流程
```
① 录入一位
   ├─ 写 localStorage（立即生效，界面刷新）        ← 主路
   └─ 该记录 push 进 pending 队列
            ↓
② 后台同步器（每 5 秒 / 页面空闲时）
   ├─ 批量 POST 云函数（带 deviceId + 口令哈希 + 记录）
   ├─ 成功 → 出队
   └─ 失败 → 指数退避重试（1s→2s→4s… 最长 5 分钟），最多 20 次
            ↓
③ 页面关闭 / 切后台 → 冲刷一次（sendBeacon 兜底，不保证成功，靠下次打开补传）
            ↓
④ 页面右上角极轻指示：☁️ 已同步 / ☁️ 待同步 3 / ⚠️ 口令错误
```

### 5.2 幂等与冲突
- **唯一键**：日期 + 场次 + 桌号 + 昵称 → 云函数 upsert，重复推送不产生重复行
- **冲突**：比较 `updatedAt`，最后写入者胜；**本地副本永远保留**，不会因云端覆盖而丢
- **手工改过的行**标 `manual=true`，同步时以本地为准

### 5.3 离线优先
- 断网 → 队列堆积，顶部显示「⚠️ 离线，N 条待同步」
- 恢复在线 → 自动按顺序补传
- 队列上限 500 条（超出丢弃最旧并告警）

### 5.4 多设备同时录同一桌
- 各自录各自桌 → 无交集
- 万一撞了 → 唯一键 upsert，后写覆盖，并记录来源设备便于排查

## 六、安全加固清单

| # | 措施 |
|---|---|
| 1 | `app_id` / `app_secret` **只存云函数环境变量**，代码库不放明文 |
| 2 | 前端只存**口令哈希**，明文口令输入后即丢弃 |
| 3 | 云函数校验：口令哈希匹配 + deviceId 未被停用 |
| 4 | 云函数限流：单设备 ≤ 30 次/分钟、≤ 500 场次/天 |
| 5 | 字段校验：昵称 ≤ 12 字、数值范围、应到人数 ≤ 30 |
| 6 | 写入前转义表格公式（`=`、`+`、`-`、`@` 开头加 `'` 前缀）防注入 |
| 7 | 飞书表格权限：**仅你可编辑**；牌友如需查看，给「可阅读」 |
| 8 | 云函数日志只打 deviceId 短码，不打完整昵称 |
| 9 | 提供「暂停同步」开关（设置里一键关） |
| 10 | 口令定期更换（建议按月或按牌局季），改飞书表一行即可 |
