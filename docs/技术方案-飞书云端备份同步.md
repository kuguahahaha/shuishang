## 〇、先回答你的风险问题

### 结论 1：GitHub Pages 本身不是风险源，**「浏览器直接调飞书写入」才是**

| 误解 | 事实 |
|---|---|
| 「托管在 GitHub 上所以有风险」 | ❌ 换任何静态托管（腾讯云 COS、CloudBase 静态站、Vercel）都一样——**浏览器里跑的 JS 谁都能 F12 看到**。托管在哪不是风险本质 |
| 「那放自己服务器就安全了」 | ❌ 前端代码照样公开。**只要凭据在浏览器里，就是公开的** |
| 「所以不能上传」 | ✅ **能上传**——前提是飞书凭据不进前端 |

### 结论 2：纯静态页 **无法** 安全直连飞书写入
1. **凭据泄露**：`app_secret` 写在前端 → 任何访客都能拿到 → 可读写甚至清空你的表格
2. **跨域限制**：飞书开放 API 不支持浏览器直连，必须服务端中转

### 结论 3：解法是加一个**零成本的免费云函数**
```
Record.html
  ├─ localStorage  ← 主数据源（即时、离线可用）
  └─ 待同步队列 → CloudBase 云函数（★密钥只在这）→ 飞书多维表格
```
> **一句话**：托管在哪不重要，**凭据放哪才重要**。

## 一、使用场景（已按确认调整）

```
牌友A的手机 ─┐                        ┌─→ 飞书多维表格（统一汇总）
牌友B的手机 ─┼→ localStorage → 云函数 ┤
牌友C的手机 ─┘   （各自录各自桌）      └─→ 云函数（校验口令 + 审计）
管理员的手机 ─┘
```

| 确认项 | 结论 |
|---|---|
| 飞书账号 | **个人版飞书**（可建自建应用，够用） |
| 同步方向 | **单向备份**：本地 → 飞书（不回读） |
| 鉴权方式 | **统一口令**（私下分发，首次输入一次） |
| 使用者 | **牌友各自录**（每人用自己手机） |
| 角色 | **管理员 / 普通用户**，管理员多一个管理员口令 |
| 数据归属 | 按 **日期 + 场次 + 桌号** 分组，一桌一人录 |

**各方看到的**：
- 牌友：只看到自己录的数据（不回读），录完自动备份，全程无感
- 管理员：在网页里多一个「全部场次」入口；全局汇总在飞书表格
- 牌局的账：每桌各自算自己的筹码差额（应到人数各自填），互不干扰

## 二、口令机制

### 2.1 口令怎么工作
```
① 首次打开网页 → 弹框「请输入团队访问口令」
② 输入口令 → 前端用 Web Crypto 算 SHA-256 哈希
   ★ 只把【哈希】存本地，之后每次请求带哈希，明文口令不落盘
③ 云函数比对哈希（云端存的是同一哈希值，不是明文）
   → 一致：放行写入
   → 不一致：拒绝（结算面板显示一行提示）
```

| 设计点 | 为什么 |
|---|---|
| 口令明文不落盘 | 前端只存哈希，浏览器被翻也拿不到明文 |
| 云端只存哈希 | 云函数被读也拿不到明文口令 |
| 口令强度要求 | ≥ 8 位随机字符（大小写+数字），避免被猜 |

### 2.2 口令怎么改（换设备 / 泄露时）
口令哈希值存飞书「设备表」，改一行即可：

| 步骤 | 操作 |
|---|---|
| 改团队口令 | 改「当前口令哈希」→ **所有设备下次请求被拒**，重新输入新口令即可 |
| 改管理员口令 | 改「管理员口令哈希」→ 管理员需重新输入 |
| 停用某人 | 把该 deviceId 的状态改为「停用」→ 该设备立刻无法写入 |
| 查是谁写的 | 设备表记录每个 deviceId 的首次/最近时间、累计写入行数；记录表每行带「来源设备」 |

> 所以 **deviceId 仍然记录**，但角色从"准入门槛"变成"**审计与单独停用**"——口令管准入，deviceId 管追责。

### 2.3 口令的风险与缓解
| 风险 | 缓解 |
|---|---|
| 口令在群里转发扩散 | ① 按桌/按季更换；② deviceId 可单独停用；③ 出问题能定位到具体设备 |
| 牌友换手机 | 新设备首次再输一次（输入框会记住哈希，直接放行） |
| 哈希被撞库 | 口令 ≥8 位随机字符 practically 撞不动 |

## 三、数据归属与去重

### 3.1 分组键
| 日期 | 场次 | 桌号 | 昵称 | ... |
|---|---|---|---|---|
| 2026-10-29 | 下午场 | A | captain | ... |
| 2026-10-29 | 下午场 | B | nuy | ... |

→ 按「日期 + 场次」筛选 = 看当天所有桌；按「桌号」筛选 = 某一桌。

### 3.2 唯一键与去重
```
唯一键 = 日期 + 场次 + 桌号 + 昵称
```
- 同一键重复推送 → **upsert 覆盖**，不产生重复行
- 两人误录同一桌同一人 → 后写的覆盖先写的（按 updatedAt）

### 3.3 约定
**「一桌只由一人录」** —— 避免两个人同时录同一桌打架。牌局开始时在群里说清：A 桌谁录、B 桌谁录。

## 五、同步机制（无感 + 不丢数据）

### 5.1 主流程
```
① 录入一位
   ├─ 写 localStorage（立即生效，界面刷新）        ← 主路
   └─ 该记录 push 进 pending 队列
            ↓
② 后台同步器（每 5 秒 / 页面空闲时）
   ├─ 批量 POST 云函数（带 deviceId + 口令哈希 + 记录）
   ├─ 成功 → 出队
   └─ 失败 → 指数退避重试（1s→2s→4s… 最长 5 分钟），最多 20 次
            ↓
③ 页面关闭 / 切后台 → 冲刷一次（sendBeacon 兜底，不保证成功，靠下次打开补传）
            ↓
④ 结算面板底部展示一行备份状态（**唯一出现备份信息的地方**，见 §11.3）
```

### 5.2 幂等与冲突
- **唯一键**：日期 + 场次 + 桌号 + 昵称 → 云函数 upsert，重复推送不产生重复行
- **冲突**：比较 `updatedAt`，最后写入者胜；**本地副本永远保留**
- **手工改过的行**标 `manual=true`，同步时以本地为准

### 5.3 离线优先
- 断网 → 队列堆积，联网后自动按序补传
- 队列上限 500 条（超出丢弃最旧并告警）

## 六、安全加固清单

| # | 措施 |
|---|---|
| 1 | `app_id` / `app_secret` **只存云函数环境变量**，代码库不放明文 |
| 2 | 前端只存**口令哈希**，明文口令输入后即丢弃 |
| 3 | 云函数校验：口令哈希匹配 + deviceId 未被停用 |
| 4 | 云函数限流：单设备 ≤ 30 次/分钟、≤ 500 场次/天 |
| 5 | 字段校验：昵称 ≤ 12 字、数值范围、应到人数 ≤ 30 |
| 6 | 写入前转义表格公式（`=`、`+`、`-`、`@` 开头加 `'` 前缀）防注入 |
| 7 | 飞书表格权限：**仅管理员可编辑**；牌友如需查看，给「可阅读」 |
| 8 | 云函数日志只打 deviceId 短码，不打完整昵称 |
| 9 | 提供「暂停备份」开关（设置里一键关） |
| 10 | 口令定期更换（改飞书表一行即可） |

## 十、角色权限（v1.2 新增）

| 角色 | 凭据 | 可见范围 | 可做操作 |
|---|---|---|---|
| **普通用户** | 团队口令（哈希比对） | **只看到自己录入的场次** | 录入、结算、导出自己那桌 |
| **管理员** | 团队口令 **+** 独立的管理员口令 | **看到全部场次** | 追加：查看全部、停用设备、改团队口令、导出全局汇总 |

**实现要点**
1. 管理员口令在飞书「设备表」里**单独存一条哈希**，与团队口令互不影响
2. 前端提交两个哈希值，云函数分别校验；管理员身份**只在拉取场次列表时生效**，写入权限两者相同
3. 管理员口令错误时**静默降级为普通用户**（不弹错误、不显示管理员入口），避免暴露管理员账号存在
4. deviceId 记录「该设备绑定的角色」，用于审计

## 十一、要不要分两个页面？（结论：不分）

| 方案 | 成本 | 结论 |
|---|---|---|
| 同一页面按角色渲染 | 0 | ✅ **采用** |
| 两个独立页面 admin.html + record.html | +1~2 人天，且以后每改一处要改两处 | ❌ |

**差异只落在一处**：场次列表（历史场次区块）
- 普通用户：只列出 `deviceId === 当前设备` 的场次
- 管理员：多一个「全部场次」开关，列出所有设备的场次

其余（录入区、结算面板、导出、设置）**完全共用同一套代码**，管理员额外解锁几个按钮而已。

> **全局汇总的真正主场是飞书表格**：那里有全部数据、还能多维筛选（按日期/场次/桌号/来源设备）。网页里的「全部场次」只是方便管理员随手翻一下。

## 十二、界面无感规范（v1.2 新增，硬性要求）

> 「同步这类字眼都不要出现，放在结束录入后再展示计算出来的结果」

### 12.1 禁止出现的位置
| 区域 | 禁止内容 |
|---|---|
| 页面顶部标题栏 | 任何同步/上传/云端/备份状态图标与文字 |
| 录入区（面额、黄卡、实时结果） | 任何同步相关字样 |
| 记录表每一行 | 同步状态标记（如小云朵图标） |
| 导出按钮区 | 「同时同步到云端」之类的说明 |
| 首次绑定弹窗 | 用词避开「同步」，改用「团队访问口令」「汇总到团队表格」 |

### 12.2 允许出现的位置：**只有结算面板底部一行**
```
🥇 第一名 somuns      🥈 第二名 辉        🥉 第三名 Today
   462,000 · +161分     258,000 · +59分     244,000 · +52分

筹码差额：Σ总码量 1,612,000 − 16万×10 = +12,000（上限 3 万）  合格
需支付合计：¥160  |  已录 9 / 应到 10 人（还差 1 人）

─────────────────────────────
✓ 已备份到团队表格
```

| 后台状态 | 结算面板底部那一行显示 |
|---|---|
| 全部已上传 | `✓ 已备份到团队表格` |
| 部分待传 / 离线 | `⚠ 3 条待上传（网络恢复后自动补传）` |
| 口令错误 | `⚠ 访问口令有误，数据仅保存在本机，请联系管理员` |

> 口令错误属于**异常路径**，必须提示——否则用户不知道数据没备份上去。正常路径下一个字都不提。

### 12.3 首次绑定弹窗文案（避开「同步」）
```
┌──────────────────────────────┐
│  团队访问口令                  │
│  首次使用需输入一次团队口令，   │
│  用于把你的记录汇总到团队表格。  │
│  ┌──────────────────────┐    │
│  │                      │    │
│  └──────────────────────┘    │
│      [ 绑定本机 ]  [ 取消 ]     │
└──────────────────────────────┘
```
绑定成功后该弹窗**永不再出现**，页面也不留任何同步痕迹。

### 12.4 实现方式
| 需求 | 实现 |
|---|---|
| 录入中零提示 | 前端同步层**不渲染任何状态 UI**，只维护内部队列计数；状态只在结算面板渲染时读取一次 |
| 结束后才展示 | `renderSettle()` 里追加一个 `#backupStatus` 行，根据内部状态填文案 |
| 首次绑定一次 | 绑定成功后把哈希写入 localStorage，`hasToken` 为真则不再弹窗 |
| 角色切换 | 管理员额外输入一次管理员口令，成功后 `isAdmin=true` 存本地；页面多显示「全部场次」开关 |
| 场次过滤 | 历史列表渲染时按 `isAdmin` 决定是否过滤 `deviceId` |
