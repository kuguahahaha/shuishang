## 一、背景与目标

线下牌局目前用**纸质表格**记录（《水上俱乐部 · 活动签到与积分记录表》），手工填写、事后手算排名与筹码差额，容易看错行、算错数。

本需求的目标：**把现有筹码计算工具扩展成「逐人录入 → 自动排名 → 自动核对差额 → 导出截图」的一条龙**，仍然**不接数据库**——数据只存在本机，靠导出文件带走去对账。

**核心诉求（用户原话归纳）**
1. 记录：玩家昵称、本场积分、总码量
2. 排名：按**总码量**排前三名
3. 核对：筹码差额必须 **≤ 3 万**
4. 交互：**逐个录入**，录完一个点「确定」再录下一个，避免看错行
5. 产出：自动生成**排名表**和**筹码差额**
6. 交付：**需要能截图**（把结果表分享到群里）
7. 不使用数据库，沿用现在的计算工具逐个人录入

## 二、术语与核心概念

| 术语 | 定义 | 来源 |
|---|---|---|
| **初始码** | 每名玩家每场次的初始码量 = **16 万** | 用户口述 |
| **黄卡** | 每人初始 7 张，1 张 = **2 万筹码**（7 张 = 14 万） | 用户口述 + 纸表 |
| **桌面筹码** | 玩家当前在桌上的实际筹码（现有计算工具算出来的那个数） | 现有工具 |
| **总码量** | **桌面筹码 + 黄卡折算筹码** | 用户口述 |
| **本场积分** | 本场积分增减（可正可负） | 纸表 |
| **初始积分** | 玩家历史累计积分（纸表手填） | 纸表 |
| **筹码差额** | Σ各人总码量 − 16 万 × 人数，**必须 ≤ 3 万** | 用户口述 + 纸表备注 |
| **爆发** | 玩家码量不足以赔付时的特殊结算 | 纸表批注 |

### 总码量举例（用户原话）
> 「黄卡就是 7 张 14 万筹码，比如水上 10 万，没有黄卡使用记录，那就是 14 + 10 万等于 24 万」

```
某玩家：剩余黄卡 7 张（14 万）+ 桌面筹码 10 万  →  总码量 24 万
```

## 三、计算规则（已用纸表数据反推验证）

### 3.1 总码量

```
总码量 = 桌面筹码 + 黄卡张数 × 20000
```

### 3.2 本场积分（核心公式，已验证）

```
本场积分 = 总码量 ÷ 2000 − 70
          （70 = 7 张黄卡 = 14 万筹码 = 70 分，即「黄卡基准分」）
```

**用 10-28 下午场第 2 桌的真实数据验证（9 人）**：

| 昵称 | 初始积分 | 纸表本场积分 | 总码量 | 总码量÷2000 | 公式值 | 差 |
|---|---|---|---|---|---|---|
| captain | 55 | −68 | 0 | 0 | −70 | **+2（封底）** |
| nuy | 180 | +5 | 150000 | 75 | **+5** | 0 ✅ |
| 辉 | 150 | +59 | 258000 | 129 | **+59** | 0 ✅ |
| somuns | 181 | +161 | 462000 | 231 | **+161** | 0 ✅ |
| Daaa. | 740 | +45 | 230000 | 115 | **+45** | 0 ✅ |
| 陈锋 | 0 | −50 | 50000 | 25 | −45 | **−5（被爆发）** |
| Today | 100 | +52 | 244000 | 122 | **+52** | 0 ✅ |
| Aaron | 有 | −20 | 106000 | 53 | −17 | **−3（被爆发）** |
| Freecat | 0 | −20 | 112000 | 56 | −14 | **−6（被爆发）** |

> **公式在「无爆发」的 6 人身上完全吻合**，差异全部集中在爆发相关行 → 说明公式正确，爆发是另一套附加机制。

### 3.3 筹码差额

```
筹码差额 = Σ(各人总码量) − 160000 × N
N = 本场人数（到场 + 未打完的，按纸表口径）
```

**验证（同一场）**：Σ总码量 = 1612000，N = 10 → 1612000 − 1600000 = **12000**（1.2 万 ≤ 3 万 ✅）
与纸表备注「1612000 − 16w×10 = 12000」**完全一致** ✅

另一场（10-28 15:00 第一桌）：「146w+k − 146w = 2k」→ 差额 2000，同样通过。

### 3.4 排名

按**总码量降序**取前三名（纸表：第一名 somuns 462000 / 第二名 辉 258000 / 第三名 Today 244000 ✅ 与总码量一致）。

### 3.5 总码量为 0 的特殊处理

> 用户口述：「总码量 0 的话就是积分减 68」

```
总码量 = 0  →  本场积分 = −68   （而非公式值 −70）
```
纸表中 captain、Jonny soso、史蒂夫 三人总码量均为 0、本场积分均为 −68 ✅

## 五、交互流程设计（核心：逐人录入，防看错）

```
① 打开页面 → 选择「新建场次」：日期 / 场次 / 桌号 / 人数 N
      ↓
② 进入「录入模式」：屏幕只显示【当前这一位】玩家的录入区
      ↓
   ┌──────────────────────────────────────┐
   │  第 3 / 10 位                        │
   │  昵称 [____________]                  │
   │  桌面筹码：复用现有面额计算器          │
   │  黄卡 [__] 张                        │
   │  ─────────────────────────────       │
   │  总码量  240000                       │
   │  本场积分  50                         │
   │  [ 确定并录入 ]   [ 跳过 ]            │
   └──────────────────────────────────────┘
      ↓ 点「确定并录入」→ 写入一行 + 写入下方的记录表 + 立刻显示下一位
      ↓
③ 录完 N 位 → 自动弹出【结算面板】：
   · 排名表（前三名高亮 🏆）
   · 筹码差额（Σ总码量 − 16w×N），> 3 万 → 红色告警
   · [ 导出 Excel ] [ 复制表格文本 ] [ 截图/保存图片 ]
```

### 防看错的具体措施
| 措施 | 说明 |
|---|---|
| 一次只显示一位 | 录入区只有当前玩家，其余人不显示在录入区（避免左右串行） |
| 录入区固定显示「第 k / N 位」 | 明确当前进度 |
| 每行录入后立即入表 | 下方记录表实时追加一行，录错能立刻看到并删除/重录 |
| 录入区显示**实时计算结果** | 总码量、本场积分当场算出，录完再确认 |
| 「确定并录入」独立按钮 | 避免边输边算造成的误判；Enter 键也可提交 |
| 已录入行可点开重录 | 支持修改昵称、筹码、黄卡 |
| 结算面板二次确认 | 录完所有人才生成排名，避免半成品被当成结果 |

### 录入时的筹码输入（复用现有工具）
现有页面已经能算「桌面筹码 → 结算筹码 → 积分」，本需求把它拆成**录入场景**：
- 复用 7 个面额输入（500/1000/5000/1W/5W/10W/100）+ 实时显示桌面筹码合计
- **黄卡张数输入框（0~7）** 放在同一区域（与现有页面同一套校验）
- 本场积分按 3.2 公式算，不再用「整张卡抵扣」那套（两者用途不同，见 8.3）

### 8.3 口径差异提醒（重要）

现有计算工具的积分逻辑是 **「整张卡抵扣」**（净筹码 = 桌面筹码 − 已抵扣整卡），而本需求的本场积分是 **「总码量 ÷ 2000 − 70」**。两者**用途不同**：
- 现有工具：算**某人单场输赢多少积分**（黄卡按整张抵扣）
- 本需求：算**某场结束后所有人的码量守恒与排名**（含未使用黄卡）

建议**两套口径并存、界面上明确标注**，不要混用，以免对账时打架。
