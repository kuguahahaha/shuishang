# 积分记录表（Record.html）使用说明

> 文件：`Record.html`（单文件，零依赖，双击即可用）
> 版本：v1.0（本地版，**未上线**）
> 日期：2026-10-29
> 需求来源：`docs/需求-积分记录表与排名结算.md`（v2.0 定稿）

---

## 一、这是什么

线下牌局的**积分记录表**电子版：逐个人录入昵称与筹码 → 自动算本场积分 → 自动排前三名 → 自动核对筹码差额 → 导出整表截图发群里。

**不用数据库**，数据存在自己手机/电脑的浏览器里（localStorage），刷新关机都不丢。

---

## 二、怎么用（现场流程）

### ① 开场：填场次信息
| 字段 | 说明 |
|---|---|
| 日期 | 默认今天 |
| 场次 | 如「下午场第2桌」 |
| 桌号 | 如 A |
| **应到人数** | 默认 10，**差额校验用它** |
| 记录人 / 审核人 / 评分 | 选填，会出现在导出的表上 |

### ② 逐人录入（防看错的关键）
1. 点昵称输入框 → 填玩家昵称
2. 在 7 个面额里填**桌上现有的筹码**（500 / 1000 / 5000 / 1W / 5W / 10W / 100），下方实时显示桌面筹码合计
3. 填**剩余黄卡张数**（0~7，默认 7）
4. 实时结果立刻出来：
   ```
   桌面筹码  140,000 ｜ 总码量 280,000 ｜ 本场积分 +70 ｜ 需支付 ¥0
   ```
5. 点「**录入下一位**」→ 写入表格并自动清空，进入下一位
   - 昵称框按 **Enter** 效果相同
   - 录错可以点该行「**改**」重新载入修改，点「**✕**」删除
6. 所有人录完后点「**结束录入**」→ 弹出确认（会告诉你已录几人、还差几人）→ 跳到结算区

### ③ 看结算
```
🥇 第一名 somuns      🥈 第二名 辉        🥉 第三名 Today
   462,000 · +161分      258,000 · +59分     244,000 · +52分

筹码差额：Σ总码量 1,612,000 − 16万×10 = +12,000（上限 3 万） 合格
需支付合计：¥160   |   已录 9 / 应到 10 人（还差 1 人）
```
- 差额 **> 3 万** 会变**红色告警**，提示需要复核
- 差额为负不告警（按约定不管）

### ④ 导出
| 按钮 | 产出 |
|---|---|
| **导出整表截图** | PNG 图片（和纸质表同款：标题 + 数据表 + 三名 🏆 + 差额 + 记录人/审核人/评分）。会弹出预览层，**手机上长按图片即可保存到相册** |
| **导出 CSV** | Excel 可直接打开（已加 UTF-8 BOM，中文不乱码） |
| **复制表格文本** | TSV，可直接粘到微信或 Excel |
| **导出 JSON / 导入 JSON** | 换手机、备份用 |

## 三、计算规则（已用纸表 9 人数据验证 9/9）

```
总码量 C = 桌面筹码 + 剩余黄卡 × 20000
欠卡数 K = max(0, ceil((140000 − C) ÷ 20000))      ← 为还清 7 张黄卡（14万）
需支付   = K × 10 元
剩余筹码 = C + K×20000 − 140000
本场积分 = floor(剩余筹码 ÷ 2000)                   ← 向下取整
           ※ C = 0 时强制记 −68（积分复活，既往不咎）
筹码差额 = Σ各人总码量 − 160000 × 应到人数          ← > 30000 才告警
排名     = 按总码量 C 降序取前三（同分并列）
```

**验证样例**（10-28 下午场第 2 桌，纸表真实数据）：

| 昵称 | 总码量 | 欠卡 | 需支付 | 本场积分 | 纸表 |
|---|---|---|---|---|---|
| captain | 0 | 7 | ¥70 | −68 | −68 ✅ |
| nuy | 150000 | 0 | ¥0 | +5 | +5 ✅ |
| 辉 | 258000 | 0 | ¥0 | +59 | +59 ✅ |
| somuns | 462000 | 0 | ¥0 | +161 | +161 ✅ |
| Daaa. | 230000 | 0 | ¥0 | +45 | +45 ✅ |
| 陈锋 | 50000 | 5 | ¥50 | +5 | 5 ✅ |
| Today | 244000 | 0 | ¥0 | +52 | +52 ✅ |
| Aaron | 106000 | 2 | ¥20 | +3 | 3 ✅ |
| Freecat | 112000 | 2 | ¥20 | +6 | 6 ✅ |

合计：Σ总码量 1612000 − 16万×10 = **+12000**（≤3 万 ✅），支付合计 **¥160** —— 与纸表备注完全一致。

## 四、关键设计说明

| 设计 | 为什么 |
|---|---|
| 一次只显示一位录入 | 避免左右串行看错行 |
| 录入区实时显示三个结果 | 录完再确认，数字当场就能验 |
| 「录入下一位」独立按钮 | 防止边输边算造成误判 |
| 录入后立即清空昵称与面额 | 彻底避免上一位的数据串到下一位 |
| 「结束录入」才出结算 | 半成品不会被当成最终结果 |
| 每行有「改」「✕」 | 现场录错能立刻纠正 |
| 结算前弹确认（含还差几人） | 防止漏人就把表发出去 |

## 五、数据与隐私

- 数据只存在**本机浏览器**（localStorage，键名 `wc_record_sessions_v1`），最多保存 50 场
- **不联网、不上传**（整页零外部依赖，连字体图标都是纯 CSS）
- 换设备：导出 JSON → 新设备导入 JSON
- 清缓存会丢数据，**重要场次请导出 PNG 或 JSON 存档**

## 七、团队协作（可选，默认关闭）

> 完整部署步骤见 `docs/部署指引-飞书备份.md`。不配也能用——**默认纯本机模式**，功能完全不受影响。

### 7.1 开启步骤（一次性）
1. 滑到「⚙️ 团队协作」块 → 「团队表格接口地址」填云函数地址 → 点「保存」
2. 点「重新绑定口令」→ 输入**团队口令** → 「绑定本机」
3. 管理员另点「验证管理员」→ 勾选「我是管理员」→ 输入**管理员口令**

绑定成功后弹窗**永不再出现**，之后全程无感。

### 7.2 界面表现（重要）
| 位置 | 显示 |
|---|---|
| 录入过程中（标题栏 / 录入区 / 记录表 / 导出区） | **完全不出现**任何同步、上传、云端字样 |
| 结束录入后的结算面板底部 | 唯一一行状态：<br>· `✓ 已备份到团队表格`（正常）<br>· `⚠ 3 条待上传（网络恢复后自动补传）`（离线/待传）<br>· `⚠ 访问口令有误，数据仅保存在本机，请联系管理员`（口令错，异常路径） |
| 纯本机模式（未配置接口） | `✓ 数据已保存在本机` |

### 7.3 角色
| 角色 | 认证 | 能看到 |
|---|---|---|
| 普通用户 | 团队口令 | 只看得到**自己录入**的场次 |
| 管理员 | 团队口令 + 管理员口令 | **全部场次**，另可停用设备、改口令 |

管理员口令填错时**静默降级为普通用户**（不报错、不显示管理员入口），避免暴露管理员账号存在。

### 7.4 数据怎么分组
按 **日期 + 场次 + 桌号** 分组，唯一键 `场次ID|昵称`（重复推送只覆盖不重复）。
在飞书里按「日期+场次」筛选 = 当天所有桌，按「桌号」筛选 = 某一桌。
**约定：一桌只由一人录**（两人录同一桌，同一昵称会互相覆盖）。

### 7.5 常见问题
| 现象 | 处理 |
|---|---|
| 提示「访问口令有误」 | 口令哈希对不上，用 `node -e "console.log(require('crypto').createHash('sha256').update('明文口令').digest('hex'))"` 重算并更新云函数环境变量 |
| 提示「该设备已被停用」 | 飞书设备表把该设备状态改成「正常」 |
| 一直「待上传」 | 云函数没部署好或网络不通，看浏览器控制台 + CloudBase 函数日志 |
| 换手机了 | 新手机重新绑定一次同一个团队口令即可 |

## 八、调试接口

浏览器控制台可用（只读）：

```js
__recordDebug.getSession()     // 当前场次对象
__recordDebug.getTableRows()   // 导出用的表格行数据
__recordDebug.calcRow(筹码, 剩余黄卡)   // 单人结算试算
__recordDebug.calcSummary()    // 当前差额/支付合计
__recordDebug.sha256(s)        // 口令哈希（与云函数算法一致）
__recordDebug.syncStatus()     // 备份状态 {mode, pending, error}
__recordDebug.syncIsAdmin()    // 是否管理员
__recordDebug.syncDeviceId()   // 本机设备码
```
